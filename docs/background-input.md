# 后台输入（实验分支）

基线：`fix/experiment-hotkey-and-scroll` 的 `97fc5f8`。

## 安装与运行

```powershell
python -m pip install -r requirements.txt
python fallen_doll.py
```

仅 Windows 启用 Frida 后台输入；无需单独启动 probe 脚本。
按原流程标定，首次动作自动根据游戏 HWND 获取 PID 并附加。
要求 Python 对游戏进程具有附加权限；两者运行权限不一致时请统一运行权限。
不要同时运行独立 probe 脚本或其他重复输入 Hook。

## 输入变化

- 使用用户验证成功的 V6 机制：游戏内 `GetCursorPos` 虚拟坐标、虚拟鼠标捕获、`WM_ACTIVATEAPP` 应用激活通知。
- 鼠标按下/释放、移动、键盘按下/释放及滚轮全部定向到游戏 HWND，不调用 SendInput、不拉前台、不移动物理光标。
- 键盘消息携带扫描码和释放位；主键盘 `1`、`E`、`Esc`、`J/K` 等走同一后端。
- 滚轮沿用原始 delta，120 为一格；实验列表标定回放与自动化回放使用同一后端。
- F1/F2/F3/F11/F12 是用户控制程序的全局热键，保留 `keyboard` 监听，未改成游戏输入。
- 一个会话共享给自动化、滚轮线程与标定；输入调用串行化。暂停/退出时释放按键并发送实际激活状态，卸载 Hook；退出后拒绝迟到的工作线程输入。
- 游戏重启/HWND 或 PID 变化后重新连接。附加失败、窗口失效或最小化会报错，不回退真实键鼠。

## 验证范围与限制

原 V6 的后台菜单鼠标点击已由用户实测成功。本分支的完整自动化、键盘与滚轮集成仍需在游戏电脑实测；单元测试不等于游戏验证。

**本次只替换输入，未替换截图。** 识别仍使用桌面截图，游戏需可见、未最小化，识别区域不能被其他窗口挡住。可把游戏放在另一个显示器上；输入后台有效不等于遮挡后的图像识别有效。

`move_rel` 现在移动虚拟客户区坐标并限制在客户区内，不注入 Raw Input。原部署流程中依赖真实相对输入的 360° 相机转向需要单独实测，不能将菜单点击成功视为相机控制已验证。

Hook 仅作用于游戏主模块直接发起的指定 API 调用，不保证覆盖游戏插件/其他模块的光标操作。游戏失焦产生新 `WM_ACTIVATEAPP(false)` 时，下次输入会重新激活内部状态。

正常暂停/退出会尝试恢复激活状态并卸载，失败写入错误日志。强制终止 Python、Frida/游戏异常断开时，应用状态可能未完全恢复：手动切入、切出游戏；必要时重启游戏。

## 建议游戏端检查

1. 前台/后台均测试菜单移动、点击，确认真实光标与其他窗口不受影响。
2. `E` 打开面板、`Esc` 关闭、主键盘 `1` 等按键。
3. 标定滚动回放、F11 回放、正常调速滚轮的方向和幅度。
4. F1 暂停后恢复物理操作；继续运行、关闭程序、游戏重启后检查恢复与重连。
5. 单独测试依赖相机转向的部署路径；失败时不要启用真实键鼠作为静默回退。
