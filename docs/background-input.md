# 后台输入（实验分支）

基线：`fix/experiment-hotkey-and-scroll` 的 `97fc5f8`。

## 安装与运行

```powershell
python -m pip install -r requirements.txt
python fallen_doll.py
```

Windows x64 启用 Frida 后台输入及 `windows-capture>=2.0.1` WGC 截图；无需单独启动 probe 脚本。WGC 需要支持 Graphics Capture 的 Windows 10/11。
按原流程标定，首次动作自动根据游戏 HWND 获取 PID 并附加。
要求 Python 对游戏进程具有附加权限；两者运行权限不一致时请统一运行权限。
不要同时运行独立 probe 脚本或其他重复输入 Hook。

## 输入变化

- 使用用户验证成功的 V6 机制：游戏内 `GetCursorPos` 虚拟坐标、虚拟鼠标捕获、`WM_ACTIVATEAPP` 应用激活通知。
- 鼠标按下/释放、移动、键盘按下/释放及滚轮全部定向到游戏 HWND，不调用 SendInput、不拉前台、不移动物理光标。
- 键盘消息携带扫描码和释放位；主键盘 `1`、`E`、`Esc`、`J/K` 等走同一后端。
- 滚轮沿用原始 delta，120 为一格；实验列表标定回放与自动化回放使用同一后端。
- F1/F2/F3/F11/F12 是用户控制程序的全局热键，保留 `keyboard` 监听，未改成游戏输入。
- 一个会话共享给自动化、滚轮线程与标定；输入调用串行化。暂停/退出时释放按键并发送实际激活状态，卸载 Hook；退出后拒绝迟到的工作线程输入。
- 游戏重启/HWND 或 PID 变化后重新连接。附加失败、窗口失效或最小化会报错，不回退真实键鼠。

## 验证范围与限制

原 V6 的后台菜单鼠标点击已由用户实测成功。本分支的完整自动化、键盘与滚轮集成仍需在游戏电脑实测；单元测试不等于游戏验证。

**识别、局部区域和标定截图已统一使用按 HWND 的 WGC 捕获。** 不再截取当前桌面，被其他窗口遮挡时也不会读到遮挡窗口的像素；Windows 路径失败时不回退桌面截图。跨虚拟桌面需要 WGC 仍然提供有效游戏帧，最小化不保证可用。

捕获服务共享缓存帧；游戏窗口/PID 更换时重连，尺寸不一致时等待新的帧，不拉伸模板。WGC 的可见边框与原 `GetWindowRect` 坐标不同时，仅补齐不可见边框的黑色像素以保留旧标定坐标；未匹配的尺寸/DPI 会报错，避免静默错位。缩放或分辨率变化后仍建议重新检查标定。

首帧或尺寸变化等待最多 4 秒；15 秒未收到回调则拒绝旧帧、在下一次请求重连。静止画面也可能不产生回调，因此该超时是保守策略而非游戏卡死判定。WGC 报错显示为“截图异常”，不伪装成模板缺失。退出时停止捕获线程。

菜单用 `move_rel` 仍移动虚拟客户区坐标。部署视角路径现在单独使用 `camera_move_rel`：向目标窗口投递 `WM_INPUT`，桥接模块仅为自己生成的令牌返回相对 RAWMOUSE 数据，真实 OS 输入保持原样。视角不再受客户区边缘限制，不移动物理鼠标。目标游戏是否消费并应用相对输入仍需实测；队列不消费时会报错，不静默回退到物理输入。

场景检测改为先寻找开始/结束等流程模板，再检查主页赞池。赞池不可见不再跳过实验内模板；没有正向证据仍显示“页面未知”。这不修改开始按钮与恢复体力按钮同时就绪的部署成功条件。

### 视角独立测试

先暂停自动化并进入允许鼠标转视角的游戏场景，然后运行：

```powershell
python scripts/test_background_camera.py --dx 10 --steps 12
```

8 秒内切走游戏，脚本发送 12 个向右相对输入包并在 `logs/camera_probe_*.json` 保存计数。`dataReads > 0` 仅表示游戏读取了数据，不等于视角一定旋转；请同时观察画面。失败时发该日志及主程序运行日志。

Hook 仅作用于游戏主模块直接发起的指定 API 调用，不保证覆盖游戏插件/其他模块的光标操作。应用激活监听同时覆盖目标 `WndProc` 与 `DispatchMessage`：同步 Windows 激活通知也能被记录；失焦清除旧虚拟捕获。每次后台点击前额外刷新 `WM_ACTIVATEAPP(true)`，防止手动介入再切走后，缓存状态与 Slate 状态不一致。

这不自动消除用户手动输入与自动动作同时操作同一游戏的冲突。需要手动操作时仍优先 F1 暂停，完成后继续。修复需要实测“后台点击 → 手动切入点击 → 再切走 → 自动点击恢复”的完整过程。

正常暂停/退出会尝试恢复激活状态并卸载，失败写入错误日志。强制终止 Python、Frida/游戏异常断开时，应用状态可能未完全恢复：手动切入、切出游戏；必要时重启游戏。

## 建议游戏端检查

1. 前台/后台均测试菜单移动、点击，确认真实光标与其他窗口不受影响。
2. `E` 打开面板、`Esc` 关闭、主键盘 `1` 等按键。
3. 标定滚动回放、F11 回放、正常调速滚轮的方向和幅度。
4. F1 暂停后恢复物理操作；继续运行、关闭程序、游戏重启后检查恢复与重连。
5. 单独测试依赖相机转向的部署路径；失败时不要启用真实键鼠作为静默回退。
6. 用其他窗口遮挡游戏、切换虚拟桌面，确认识别继续且未读取主桌面；最小化应明确报错。
7. 手动切入游戏并点击，再切走，确认自动点击继续；同时检查恢复过程未抢真实焦点。
